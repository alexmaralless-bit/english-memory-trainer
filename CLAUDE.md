# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository state

Documentation-first scaffold for **English Memory Trainer** — a local-first Python CLI app for learning American English with interchangeable AI tutors (Codex / Claude Code). No application code exists yet; the docs define what to build. Current phase: producing the eight design contracts listed in `docs/design-direction.md` §5 before implementation.

## Knowledge workflow (wiki constitution)

`wiki/README.md` is the constitution — read it before writing any spec. Core rules: dev knowledge lives in `wiki/` (specs = target with `[mvp]`/`[post-mvp]` phase tags, one module = one spec per `wiki/modules/_TEMPLATE.md`, terms defined once in `wiki/glossary.md`); current status lives only in `wiki/roadmap.md`; unresolved questions only in `wiki/OPEN.md`. Product forks are decided by the user, marked `[PD-YYYY-MM-DD]` — never resolve them yourself; canon is written only after a concept is explicitly approved ("ок"). Session summaries go to `staging/journal/` (append-only, provenance, never canon). Do not confuse the dev wiki with the future `memory/` learner vault generated by the engine.

Key v0.2 corrections that override the brief: learning is a flexible conversation, not school lessons — prerequisites and gates are advisory (no hard topic locks, no overdue-backlog blocking); the rigid lesson state machine is replaced by `STARTED → IN_PROGRESS → FINISHED` with mandatory evidence persistence at finish; scope is text-only modalities (reading, writing, grammar, vocabulary — listening/speaking are neither practiced nor scored, so TOEFL is covered partially: Reading, Writing, language base).

## Architecture (planned)

- Modular monolith. Modules: curriculum, assessments, evidence, scoring, scheduler, gates, lessons, learner, memory, audit, storage, adapters, cli. Modules interact only via public APIs and events and own their tables.
- A kernel is built before business modules: typed IDs, injected Clock/RandomSource, command/event envelopes, idempotency and correlation IDs, versioned policy registry, Unit of Work, transactional outbox, JSONL exporter, projection framework.
- State lives in SQLite (operational queries) + append-only JSONL event log (audit, replay) + an Obsidian vault as a readable linked projection. The vault is never a scoring source. Planned graph nodes: Topic, Session, Error, Vocabulary, Chunk, Gate, Review, Plan.
- Determinism is non-negotiable: same events, timestamps, and policy versions must always produce the same learner state; scoring must be reproducible via `trainer scoring replay`.
- The Python engine is the sole authority over learner state. The LLM tutor is replaceable; chat context is not memory. Sessions persist incrementally, so a lost chat leaves an `IN_PROGRESS` session that another agent can resume.
- Canonical agent skills live in `agent-skills/` and are synced as deterministic copies (not symlinks) to `.agents/skills/` (Codex) and `.claude/skills/` (Claude Code). No MCP.

## Commands

No executable toolchain is committed yet. Target: Python 3.12+ with `uv` where available (the existing `.venv` is 3.11.9 and should be recreated). Once the application is scaffolded, the validation baseline is:

```bash
pytest
ruff check .
ruff format --check .
trainer curriculum validate
trainer skills validate
trainer adapters compare
trainer database check
trainer memory check
trainer scoring replay
```

Run `trainer doctor` first when diagnosing a local setup. Agent-facing CLI commands must emit valid JSON on stdout when invoked with `--format json`, write diagnostics to stderr, and use stable exit codes.

## Invariant rules

- Read learner state only through the CLI. Never directly edit SQLite rows, event logs, scores, or generated memory/Obsidian files.
- Every assessment needs stored evidence; merely mentioning a topic is not evidence. Never fabricate scores for uncovered modalities.
- Finish sessions only through `trainer lesson finish`; change curriculum only through the `maintain-english-curriculum` workflow, then run the relevant validations.
- Style: four-space indentation, type annotations, `snake_case` functions/modules, `PascalCase` classes, stable lowercase dotted topic IDs (`grammar.present-perfect.result`), UTC timestamps, versioned schemas for external inputs, Ruff for lint/format.
- Never commit SQLite WAL/SHM files, secrets, or incidental generated data.
