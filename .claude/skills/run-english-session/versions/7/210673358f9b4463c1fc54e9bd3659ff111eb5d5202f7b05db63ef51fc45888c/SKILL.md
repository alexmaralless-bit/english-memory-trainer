## Required references

Перед действием полностью прочитать:

- `references/pedagogy.md` — изменяемые правила preflight, объяснения и обратной связи;
- `references/lesson-profiles.md` — выбор и полнота профилей урока.

## Steps

1. Если ученик сам назвал профиль, тему или theme, считать это согласием.
   Иначе вызвать `trainer session propose --format json`, объявить ученику
   `title`, `profile`, `reason`, длительность и agenda и получить подтверждение.
2. Запустить `session start`, передав выбранные `--profile`, `--topic`,
   `--theme` и `--expected-proposal-hash`, когда использовался proposal.
   Прочитать `lesson_arc`, `briefing.known_language` и `required_skills`.
   При resume сверить точную тройку `(skill_name, version, content_hash)`;
   если манифест пинит старую версию, прочитать её из
   `versions/<version>/<content_hash>/SKILL.md`, а не подменять active-текстом.
3. Для нового материала сначала получить факты через `curriculum show`.
   Составить авторское объяснение по правилам reference. Если полезной
   исторической/фонетической опоры в curriculum нет, можно проверить её по
   надёжному источнику; при недоступной сети просто пропустить необязательный
   экскурс. До показа сохранить весь сегмент через `teaching rendered`.
4. Пока идёт объяснение или содержательный диалог, один раз подготовить
   пакет приватных вариантов для известных непредъявленных кандидатов через
   `exercise prepare`; никогда не выводить их JSON в learner-facing канал и
   никогда не ждать завершения этой работы в разговоре с учеником. Проверять
   готовность только на границе следующего структурированного шага. Если
   пакет ещё не готов, продолжить объяснение, осмысленный диалог или уже
   объявленную неструктурированную практику; не показывать служебное ожидание.
   Для показа соблюдать порядок: `session peek`
   → `session next` → `exercise render-prepared` (либо `exercise rendered`)
   → показать только prompt. Ответ принимать одним скрытым `turn submit`;
   после исправления дать короткую повторную попытку без утечки ответа.
5. В free conversation держаться известного языка из briefing. Добавлять
   только 1–3 полезные единицы, фиксируя незнакомую единицу через
   `lexicon encounter`. Исправлять focus-ошибку сразу, второстепенные ошибки
   собирать в короткий пакет после смыслового обмена.
6. Если ученик меняет профиль/тему в активной сессии, записать
   `signal lesson_request --profile ... [--target ...] [--theme ...]`, затем
   выполнить `session replan`; не вставлять самодельные шаги в план.
7. Завершить через `session finish` только при пустом pending-наборе; иначе
   закрыть попытки/review или явно выполнить `session abandon`.
