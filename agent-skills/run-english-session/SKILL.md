## Required references

Перед действием полностью прочитать:

- `references/pedagogy.md` — preflight, дуга объяснения, обратная связь по
  стадии, темп «одно задание — одно сообщение», **вердикт тьютора**;
- `references/lesson-profiles.md` — выбор и полнота профилей урока;
- `references/lesson-report.md` — ведение журнала заданий в контексте и сборка
  `lesson_report@1` (поля, коды отказа, check → report).

## Steps

1. **Предложение.** Если ученик сам назвал профиль, тему или theme — это уже
   согласие. Иначе `trainer session propose --format json` (только чтение),
   объявить по-русски `title`, профиль, `reason`, длительность и agenda и
   получить подтверждение.
2. **Старт.** `trainer session start --profile … --topic … [--duration-minutes …]
   [--theme …] --provider … --format json --idempotency-key …` (без хэша
   предложения). Ответ содержит `brief` (`lesson_brief@1`) — прочитать его
   целиком: `lesson` (профиль, заголовок, agenda, language_envelope),
   `central_topic` (can_do, объяснительные факты, typical_errors, фреймы с
   `frame_of`/`carries`, текст реконструкции для drill), `reviews_due`
   (review_id, target_ref, dimension, подсказка смысла), advisory `plan`,
   `learner` (known_language, recent_errors, personal_lexicon, preferences,
   re_entry), `requirements` (только предупреждения) и `report_contract`
   (схема, шкала вердиктов, лимиты, `brief_hash`). Если в манифесте пин
   старой версии skill — читать `versions/<version>/<content_hash>/SKILL.md`,
   а не active-текст.
3. **Урок — целиком в чате, без вызовов системы.** План в brief — совет, а не
   сценарий: вести дугу по `references/pedagogy.md` (фреймы перед формой),
   свободно адаптироваться — если ученик уже знает материал, пропустить
   объяснение и перейти к практике. Задания — по одному в сообщении, обратная
   связь по стадии. Due-повторения из `reviews_due` — припоминание по смыслу
   RU→EN до показа формы. Для каждого задания самому решить вердикт
   `correct` / `partial` / `incorrect` (правила — pedagogy.md «Tutor verdict»)
   и держать в контексте запись журнала: показанный prompt, дословный ответ,
   вердикт, подсказки, ошибки (`learner_form` — дословная подстрока ответа,
   `correction`, `cause`), `review_id`, если задание закрывает повторение.
   Новые полезные единицы, которые ученик встретил, — кандидаты в `lexicon`
   отчёта. Время ответа не фиксировать.
4. **Смена планов.** Если ученик просит другую тему/профиль — просто перейти
   на неё в чате (advisory-план не перезаписывается); items по новой цели
   допустимы в отчёте, если цель есть в программе. Потерян чат — Claude Code
   resume восстанавливает контекст; если нужно перечитать сторону системы —
   `trainer session resume --provider … --format json --idempotency-key …`
   вернёт тот же brief.
5. **Отчёт.** В конце урока собрать `lesson_report@1` по
   `references/lesson-report.md`, записать во временный файл,
   `trainer session check-report --file … --format json` (только чтение),
   исправить каждый отклонённый item (например, `learner_form_not_in_answer`
   — процитировать ответ дословно), честно учесть предупреждения
   (`duplicate_span`, `review_unaddressed`, `requirement_unmet`), затем
   `trainer session report --file … --provider … --format json
   --idempotency-key …`.
   Полная процедура — skill `finish-english-session`.
6. **Итог ученику** — только по `trainer status --format json`: что
   практиковали, что ушло в повторения; никаких придуманных уровней. Если
   ученик ушёл, не дав полезных ответов, — `trainer session abandon` вместо
   пустого отчёта.
