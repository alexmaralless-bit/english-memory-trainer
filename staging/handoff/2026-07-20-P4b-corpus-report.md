## 2. Воспроизводимость

`tools/enrich_lexicon.py` — build-time скрипт:

```bash
python tools/enrich_lexicon.py --cache <каталог вне репо> --apply   # проставить
python tools/enrich_lexicon.py --cache <каталог вне репо> --check   # проверить дрейф
```

- отказывается писать кэш внутрь репозитория;
- сверяет sha256 каждого артефакта и **прекращает работу при расхождении**, а не продолжает с непроверенным источником;
- идемпотентен: повторный прогон снимает прежнее обогащение и выводит значения заново;
- `--check` перевыводит каждое значение и возвращает ненулевой код при расхождении с закоммиченным.

Проверено: `--apply` → `--check` проходит чисто.

### Почему многословным единицам нельзя присвоить частоту

wordfreq возвращает число для многословного входа, и соблазн его записать велик. Но это число **не наблюдаемая частота фразы**, а композиция частот токенов при допущении независимости. Проверка на pinned-источнике:

| вход | zipf |
|---|---|
| `run into` | 5.40 |
| `into run` (те же токены наоборот) | **5.40** |
| `the main advantage is` | 4.65 |
| `is advantage main the` | **4.65** |
| `purple the of` (бессмыслица) | 4.32 |
| `deadline` (реальное слово) | 4.12 |

Порядок слов не влияет на результат, а бессмысленная цепочка частых слов обгоняет реальное слово средней частоты. Записать это в `frequency_score` значило бы сфабриковать корпусные данные — ровно то, чего требует не делать §3.2. Поэтому у 161 единицы частотных полей нет вовсе.

**Это структурный факт, а не временный пробел.** Отсутствие частоты у 56% инвентаря — постоянное состояние: словарные корпуса не измеряют фразы. Инвариант зафиксирован в [[../../wiki/product/lexical-system]] §1.

### Что для лексем

Частота лексемы — сумма вероятностей всех её поверхностных форм (включая слоты-списки, `be` → `[was, were]`), переведённая обратно в Zipf. Помечено `transformations: [..., lemma-form-sum]`. Использовать частоту одной только базовой формы было бы занижением.

## 5. Кросс-проверка ручной разметки

Членство в NGSL/BSL проверяется по **lemma-family**, а не по headword: на поверхностных формах `completed` и `meeting` ложно читались бы как отсутствующие (списки содержат `complete` и `meet`). Переход на family-файлы поднял членство в NGSL со 101 до 110 и сократил «ни в одном списке» с 22 до 12.

**Результат проверки:**

- **Ноль конфликтов** в сильную сторону: ни одна единица `CORE`/`HIGH` не оказалась корпусно редкой. Ручная педагогическая разметка П.4a-bis выдержала проверку.
- **Пять занижений** — корпус поймал мою ошибку:

| Единица | zipf | band | было → стало |
|---|---:|---|---|
| `lexeme.tell` | 5.84 | very_high | USEFUL → **HIGH** |
| `lexeme.leave` | 5.80 | very_high | USEFUL → **HIGH** |
| `lexeme.feel` | 5.78 | very_high | INCIDENTAL → **USEFUL** |
| `lexeme.bring` | 5.52 | very_high | USEFUL → **HIGH** |
| `lexeme.buy` | 5.46 | high | INCIDENTAL → **USEFUL** |

`INCIDENTAL` по [[../../wiki/product/lexical-system]] §1 исключает единицу из повторений вообще. Держать там `feel` и `buy` — глаголы из первой тысячи английского — было неоправданно: я гнался за «CORE ≤ 35%» и пережал нижние bands. Введён инвариант: единица с корпусным band `very_high`/`high` не может быть `INCIDENTAL`; проверяется валидатором.

Итоговое распределение приоритетов: `CORE` 85 (29.3%), `HIGH` 138, `USEFUL` 55, `SPECIALIZED` 10, `INCIDENTAL` 2.

## 6. Дыра в контракте, вскрытая проходом

**OPEN-8 числился закрытым с формулировкой «CEFR coverage/confidence/уровень и learner_priority определены в 0.4 ([[../../wiki/modules/scoring]] §4)». Формулы `learner_priority` в 0.4 нет ни в каком виде** — поиск по всему `wiki/` не находит ни одного упоминания вне определений глоссария и самого OPEN.

Это тот же класс over-claim, что 0.4-ревью поймало на `mastery_criteria`: вопрос объявлен решённым, потому что рядом решены соседние. Строка OPEN-8 исправлена, вопрос переоткрыт как **OPEN-22**.

П.4b делает его острее: формула должна потреблять частоту, а у 56% инвентаря её нет. Молчаливая трактовка «нет частоты = редкое» вытеснила бы из повторений именно рабочие фреймы, ради которых лексикон и перебалансировали в П.4a-bis. Требование зафиксировано в OPEN-22 и как MUST в §1 лексической системы: **каждый потребитель `frequency_band` обязан явно определить поведение при его отсутствии**.

## 7. Правки контрактов

- **`wiki/product/lexical-system.md` §1**: четыре новых MUST — частота есть не у всех единиц; запрет композитных подделок (с доказательством); каждый потребитель определяет fallback; согласованность корпусного band с педагогическим. Плюс исправлен пример схемы: он показывал `chunk` с `frequency_score: 4.2`, то есть ровно то, что П.4b признал невозможным. Теперь два примера — покрытая однословная единица и многословная без частотных полей.
- **`wiki/modules/curriculum.md` §3.2**: манифест provenance и требование воспроизводимости; **закрытый словарь `transformations`** (`identity`, `authored`, `corpus-enriched`, `lemma-form-sum`, `reclassified-from-chunk`) — закрывает TODO из П.4a-bis; членство по lemma-family; частотные поля не обязательны, но частота без `source_refs` — ошибка.
- **`wiki/OPEN.md`**: заведён OPEN-22, исправлена строка OPEN-8.
