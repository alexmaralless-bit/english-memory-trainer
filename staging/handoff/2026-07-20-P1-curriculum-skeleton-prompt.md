## Что произвести (scope П.1)

Данные под новым каталогом `curriculum/` (формат — YAML по контракту):

1. **`curriculum/levels.yaml`** — 6 уровней A1…C2, у каждого стабильный id и главный **can-do результат** (из концепта).
2. **`curriculum/tracks.yaml`** — 8 треков (id, title, `from_level`), включая `everyday-online-informal` (с A1) и `toefl-reading-writing` (с B1, помечен `[post-mvp]`).
3. **`curriculum/modules/`** — по файлу на модуль. **A1.1–A2.8 — полностью** (id вида `a2.2-results-and-experience`, level, can_do, задействованные треки, список topic-id). **B1–C2 — только module-level эскиз** (id + can_do + треки, без разложения на темы).
4. **`curriculum/topics/`** — skeleton тем **только для A1–A2**. Каждая тема: стабильный dotted id (`grammar.present-perfect.result`), `cefr`, `track`, `module`, **однострочный `can_do`**, `advisory_prerequisites` (`strong`/`soft`, ссылки на другие topic-id). Больше ничего.
5. **`curriculum/README.md`** — раскладка каталога + явный список того, что осознанно **отложено** (см. ниже) с указанием владельца.

## Явно ВНЕ scope — не выдумывать (иначе будет отклонено)

- **`mastery_criteria`, dimensions-пороги, любые численные значения** — schema определяется контрактом 0.4, ещё не готова. НЕ авторить; в README указать «→ 0.4/П.2».
- **`LexicalItem`, лексикон, frequency_band, usage_policy** — работа П.4, ждёт лицензий (OPEN-15). Поле `topic.lexicon` НЕ заполнять (оставить отсутствующим). НЕ создавать лексические единицы.
- **Богатое тело темы**: `typical_errors`, `examples`, `contexts`, `explanation_language` — наполнение П.2. НЕ авторить (можно пустой заглушкой с пометкой, но лучше опустить).
- **B1–C2 темы** — только module-эскиз, без topic-файлов.

## Инварианты — самопроверка (движка/валидатора ещё нет, проверяй вручную)

- Все id — стабильные, dotted, уникальные; формат из контракта.
- Каждый модуль имеет `can_do`; каждая тема — `can_do`, `track`, `cefr`, `module`.
- `advisory_prerequisites` — **DAG без циклов**; prerequisite не имеет CEFR выше своей темы; сила только `strong`/`soft` (никаких «hard»/замков).
- Треки — ровно 8 из контракта; TOEFL-темы не порождаются ниже B1.
- Никаких прямых ссылок на несуществующие id (module/track/prerequisite резолвятся).
- Грамматика привязана к рабочей задаче (can-do), не изолирована — как в концепте.

## Правила

1. Создавать/менять **только** файлы под `curriculum/`. `wiki/`, `docs/`, `staging/` (кроме, если нужно, отчёта — см. ниже) — НЕ трогать.
2. Продуктовые развилки не решать самостоятельно. Если наткнёшься на неоднозначность (напр. точный список тем A1.5, порядок prerequisites) — оформи как вопрос в отчёте, выбери разумный минимальный вариант и пометь его `# TODO(review)`, не «замазывай».
3. Следуй концепту дословно там, где он конкретен (модули A1.1–A2.8); домысливай минимально и помечай домыслы.
