# Codex handoff — 2.7 «Демо смены тьютора» (continuation)

## Цель

Доказать сквозным, детерминированным сценарием ключевое свойство системы:
**контекст чата — не память; движок — единственный владелец состояния ученика**.
Провайдер A ведёт занятие → чат «умирает» посреди сессии → провайдер B делает
`session resume` → одним вызовом CLI получает полную картину из состояния движка
→ честно продолжает → незакрытые review-цели переживают смену → сессия
завершается штатно.

Это **демо/интеграция поверх готовых модулей 2.2–2.5**, а НЕ новый код модулей.
Заодно это первая независимая сквозная проверка модуля `adapters` (2.5).

## Обязательные утверждения (MUST теста)

- **Один вызов → полная картина**: `resume` (и `start`) возвращает tutor briefing, которого достаточно для корректного ведения — агенту не нужны ни старый чат, ни Obsidian vault.
- **AGENT_ATTACHED на каждое подключение** с правильным `provider` (A на start, B на resume), атомарно с операцией (в той же UoW).
- **Trust boundary**: вычисленный state и текст заметок в briefing физически разделены; заметка, даже если «утверждает» освоение темы, НЕ влияет на state/scoring.
- **Обязательства переживают смену агента**: незакрытая review-цель брошенной сессии остаётся обязательной; `finish` до её исхода отклоняется стабильной ошибкой, после — проходит.
- **Optimistic session revision**: конкурентная запись с устаревшей ревизией сессии отклоняется стабильной ошибкой (смоделируй две записи со stale-ревизией — это MUST из continuation §Правила и OPEN-11).
- **Детерминизм**: повторный прогон байт-в-байт идентичен (тот же FixedClock/seed → те же id/briefing).
