# П.1e — задание для Codex: каркас B1–C2 + темы TOEFL-трека

> Дата постановки: 2026-07-22. Заказчик: владелец (через Claude).
> Роадмап: `wiki/roadmap.md` строка П.1e, запись 74. Отчёт по завершении — в `staging/handoff/`.

## Цель

Ученик готовится к **TOEFL (B2–C1)**. Программа наполнена только на A1–A2 (153 темы с телами);
B1–C2 — это 2 темы-эскиза, TOEFL-трек (`toefl-reading-writing`, from_level B1) пуст.
Твоя задача — **каркас тем B1–C2 по всем применимым трекам + темы TOEFL-трека**.
Только каркас: **тела (mastery_criteria, typical_errors, examples, lexicon) — НЕ писать**, это П.2e.

## Порядок работы (важен)

B1 (ближняя зона ученика) → B2 → TOEFL-специфика → C1 → C2. Батчами с коммитами после каждого уровня.

## Что именно сделать

1. **Темы B1–C2** в файлах `curriculum/topics/b1.yaml`, `b2.yaml`, `c1.yaml`, `c2.yaml`
   (loader уже знает эти имена; тема лежит в файле своего CEFR-уровня; существующие 2 темы b1.yaml не трогать, только дополнять файл).
   Поля каркаса: `id` (lowercase dotted, `track-prefix.name.aspect`), `cefr`, `track`, `module`, `can_do`
   (по-английски, конкретное умение), `advisory_prerequisites` (`strong`/`weak` списками id),
   `dimensions`, для тем трека `grammar-engine` — обязательный `frequency_tier: big-five | core | tail`.
2. **Модули** уровней B1–C2 в `curriculum/modules/` (по одному файлу на модуль, по образцу существующих:
   `id`, `level`, `tracks`, `can_do`, `topics` — упорядоченный список).
3. **Грамматический хвост становится производственным**: по канону [PD-2026-07-21] tail-грамматика
   (conditionals 2/3, passive расширенный, past perfect, reported speech, инверсии…) обязана получить
   production-мерности на B1–B2. Заведи эти темы на B1/B2 с полными dimensions
   (`recognition, controlled_production, spontaneous_production, transfer`).
4. **TOEFL-трек** (`toefl-reading-writing`): темы academic reading (skimming/scanning, парафраз,
   inference, vocabulary-in-context, организация текста), integrated writing (чтение→конспект→синтез),
   independent/academic essay (thesis, развитие аргумента, связность, академический регистр).
   Только Reading/Writing/языковая база — **text-only scope**: никаких listening/speaking тем (OPEN-32).
5. Уровневая логика остальных треков: какие треки продолжать на C1–C2 — твоё авторское решение
   (например, informal/everyday могут разредиться, grammar-engine и writing — продолжаться);
   решения и плотность обосновать в отчёте.

## Жёсткие ограничения

- **A1–A2 не трогать побайтово**: `curriculum/topics/a1.yaml`, `a2.yaml`, существующие модули A1–A2,
  `curriculum/lexicon/**`, `curriculum/tracks.yaml`, `curriculum/levels.yaml` — read-only.
  Лексикон B1–C2 — это П.4e, НЕ твоя задача; `lexicon:` у новых тем — пустой список.
- Корневой `Irregular Verbs.md` не трогать.
- **`src/`, `tests/`, `wiki/` не редактировать.** Найдёшь противоречие в каноне — опиши в отчёте
  как предложение патча, канон правит владелец.
- **Фазовых маркеров не существует** [PD-2026-07-22]: никаких `phase`, `[mvp]`, `[post-mvp]` и
  вариантов — валидатор программы их отклоняет.
- Частоты не выдумывать: никаких `frequency_*`/`source_refs` полей без корпусного прохода (П.4b правило).
- Prerequisites — advisory: без циклов, prerequisite не выше уровня темы (валидатор проверяет),
  максимум переиспользования существующих A1–A2 тем как prerequisite'ов.
- Никаких заимствованных текстов: все формулировки can_do — свои.

## Проверка (перед каждым коммитом и в конце)

```bash
.venv/Scripts/python.exe -m pytest -q          # контент-инварианты + всё остальное зелёное
.venv/Scripts/python.exe -c "from english_trainer.cli.app import run; run(['curriculum','validate'])"
```

`curriculum validate` обязан давать **errors: 0**; warnings «body not yet authored (level B1/B2/C1/C2)»
для новых тем — ожидаемы и правильны (тела придут в П.2e).
