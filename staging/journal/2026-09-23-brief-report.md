# 2026-09-23 — «задание → отчёт»: решения и запуск работ

## Контекст

Первый живой урок (`grammar.be.identity`, program_lesson) прошёл по пошаговому протоколу: ~25 вызовов движка на 4 задания, CAS-токены на каждом шаге; план не адаптировался (сигнал ученика о своём уровне не менял шаги new_material_intro/recognition); ошибка формата `rubric_criterion_ref` молча и необратимо сделала свободный ответ non-contributing; `session start` с `--profile/--topic` ложно отвечал «stale proposal»; верный ответ без конечной точки засчитан как неверный (OPEN-43). До урока — повторный placement прерван учеником; зафиксирован `placement decline`; по ходу найдены OPEN-40…42.

Ученик: «движок не должен быть таким жёстким бюрократом и диктовать урок. Ты препод всё-таки, а он должен просто предлагать уроки, темы и так далее, и фиксировать правильные результаты… урок должен приходить тебе как промпт с описанием и требованием к уроку, а в конце урока ты уже можешь загружать отчёт по уроку по форме».

## Принятые решения [PD-2026-09-23]

- **PD-A**: протокол тьютор↔движок — два вызова: brief на старте, один отчёт в конце; пошаговая доставка (`session next`, `exercise rendered`, `attempt record` …) удаляется.
- **PD-B**: обрыв чата восстанавливается контекстом Claude Code (`resume`); локального черновика и промежуточных чекпойнтов нет («не надо усложнять»).
- **PD-C**: правильность задания решает тьютор («ты решаешь правильно или нет выполнено задание»); движок хранит evidence (prompt, дословный ответ, вердикт, причина ошибки) и детерминированно агрегирует. Разворачивает `docs/design-direction.md` «агент не выставляет себе оценки» и OPEN-4.
- **PD-D**: шкала `correct 1.0 / partial 0.5 / incorrect 0`; partial закрывает повторение как CONFIRMED.
- **PD-E**: автоматизм в чат-уроках — только точность; latency не передаётся; `automatic` пока недостижим.
- **PD-F**: trust-cap на вердикты тьютора не вводится; проверка — постфактум аудитом.
- **PD-G**: требования brief'а — только предупреждения; отчёт не отклоняется за неадресованную тему/повторения.

Исполнение: субагенты — Opus 5.5 для сложного, Sonnet 5 для среднего/простого; приёмка — владелец (полный pytest, ruff, mypy strict, живой урок).
